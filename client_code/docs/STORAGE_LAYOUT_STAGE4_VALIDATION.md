## 관측된 제한

1. 웹캠 index 0은 열기 성공 후 첫 프레임 수신이 실패하는 상황이 있었다. 다른 카메라 프로그램을 닫은 뒤에도 한 차례 재현되어 프로그램 점유만을 원인으로 단정하지 않는다. 후속 독립 점검에서는 기본 640×480 3회, 제품 요청 프로파일 1280×720/24FPS 6회 수신이 모두 성공했다. 관련 점검 JSON은 C 원자료에 있다.
2. D의 실제 저장 프레임 크기는 최초 1280×720, 재시작 640×480으로 달랐다. 요청 프로파일의 일관된 적용은 보장하지 못했다. 재시작 crop 미완료와 해상도 변화의 인과관계는 확인하지 않았다. 전신/크기/선명도 중 어떤 기준이 탈락 원인인지 별도 계측하지 않았다.
3. D 최초 원본의 약 10초 구간이 220프레임/24FPS, 약 9.167초로 재생됐다. 초기 지연과 기존 프레임 보정 한도 메시지도 관측했다. 파일 재생 성공을 무손실·정확한 실시간 길이 보장으로 표현하지 않는다. 이후 10초 원본은 240프레임/10초였다.
4. 서로 다른 사람·다중 카메라 재식별 정확도, RTSP 장애/복구, 제품 GUI의 실제 저장 위치 선택, 장시간 메모리·디스크 부하, 강제 종료 후 복구는 검증하지 않았다. 저장소 보존 기간·자동 잔여 파일 복구는 이번 구현 범위가 아니다.

## 재실행 방법

실행 디렉터리: `C:\GitHub_Clone\AI_CCTV`.

```powershell
.\venv311\Scripts\python.exe -B client_code/tests/manual_storage_layout_probe.py --indices 0 --seconds 15 --label webcam_retry_01
```

`label`에는 영문/숫자/밑줄/하이픈만 사용한다. 예: `webcam_retry_01`. 기존 이름은 거부해 앞선 자료를 보존한다. 실행 전 다른 카메라 프로그램을 닫고 두 관측 구간 동안 전신이 화면 안에 들어오도록 한다. 실제 이중 카메라가 사용 가능한 경우 `--indices 0 1`로 첫 카메라 STOP/재시작 중 두 번째 카메라 수신 유지도 확인할 수 있다.

이번 제한 환경에서는 venv 실행기가 원래 Python 경로를 찾지 못해 가용 `python3.11.exe`에 `PYTHONPATH=C:\GitHub_Clone\AI_CCTV\venv311\Lib\site-packages`를 연결했다. 패키지는 설치/업그레이드하지 않았다. 진단용 Ultralytics 설정은 진단 output 내부에 두며, 첫 시도의 설정 경로 fallback으로 생성된 파일 두 개도 해당 시도의 `ultralytics-fallback`에 보존했다. 사용자 설정은 수정하지 않았다.

진단 스크립트의 문법·`--help`와 `git diff --check`를 확인했다. 제품 코드 변경이 없어 3단계의 자동 검증 87개를 반복 실행하지 않았으며, 과거 자동 통과를 이번 실제 장치 전체 통과로 간주하지 않는다.
