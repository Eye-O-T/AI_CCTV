# 관제 프로그램 이벤트 타임라인 개발 계획

- 기준일: 2026-11-20. 현재 **1~3단계 구현 완료**다. 검증은 임시 서버/DB·합성 입력·offscreen 관제 창 범위이며 실제 촬영 중 타임라인/장시간 검증은 남아 있다.
- 타임라인 UI 수정 또는 이력 조회/자동 반영 연결 전에 이 문서를 읽는다.
- 기존 카메라 목록·전체/개별 보기·버튼·통계·저장 경로 표시를 유지하고 오른쪽에 패널을 추가한다. 같은 창 크기에서는 영상의 가로 공간이 줄어든다.
- DB·API·이벤트 발생 기준·영상/AI/녹화 로직은 변경하지 않는다. 저장 계약은 [이벤트 MVP 개발 계획](EVENT_MVP_DEVELOPMENT_PLAN.md)을 따른다.

## 표시 계약

- 폭 300px, 시간과 간단한 내용 두 줄 카드. `CAM-01 · 카메라 실행/중지`, `CAM-01 · 인물 #7 등장/사라짐`. 인물 번호는 글로벌 ID다.
- 한국 시간(UTC+9), 날짜 구분선, 발생 시각 내림차순/동률이면 event_id 내림차순. event_id 중복은 한 카드로 표시한다.
- 종류별 색상과 문구, 빈 상태, 세로 스크롤, 긴 식별자 줄바꿈을 제공한다.
- 모든 카메라의 통합 목록이며 카메라 선택과 독립적이다. 썸네일·상세/재생·검색·필터·알림은 제외한다.

## 단계

| 단계 | 범위 | 상태 |
| --- | --- | --- |
| 1 | 독립 패널/카드·빈 상태·정렬·날짜·스크롤·관제 창 연결 | 완료 |
| 2 | 별도 비동기 조회·최근 50건·커서 기반 이전 이력·오류/인증/세션 취소 | 완료 |

2단계 조회는 저장 큐와 분리한다. 3단계는 미디어 PATCH를 새 이벤트로 표시하지 않는다. 기존 정상 종료·저장 큐·로그아웃 순서를 보존한다. 각 단계는 사용자 승인 범위에서 진행한다.

## 1단계 구현·검증

- `ui/event_timeline.py`: 표시 전용 EventTimeline/EventCard. `set_events()`로 전달된 목록을 표시한다. aware datetime 또는 API ISO 시각을 사용한다. API 호출·DB 접근·샘플 자동 주입은 없다.
- `ui/gui.py`: 기존 본문 오른쪽에 패널을 추가했다. 1단계 당시에는 빈 상태만 표시했다. 현재 이력 조회/자동 반영은 아래 2~3단계 구현을 따른다.
- `tests/test_event_timeline.py` 3개 통과: 빈 상태/교체, UTC→한국 날짜 경계·동률 정렬·중복·글로벌 ID 문구, 60개 카드 세로 스크롤·긴 ID 줄바꿈·가로 넘침을 확인했다. 최초 검증의 스크롤/긴 문구 높이 문제를 수정한 뒤 전부 통과했다.
- 실제 CCTVMainWindow를 offscreen으로 생성해 전체 보기 4칸/개별 보기 1칸과 기존 버튼·패널 배치를 확인했다. 1600×900/1280×720에서 렌더링했다. offscreen 폰트 누락으로 렌더 검증 프로세스에서만 Windows Arial/맑은 고딕을 등록했고 제품 폰트는 변경하지 않았다.
- 스크린샷: `temp/event_timeline_stage1/empty_1600.png`, `cards_1600.png`, `cards_small.png`. 카드는 검증 전용 예시 데이터이며 실제 이력이 아니다.
- 실제 서버·카메라·운영 DB/설정·기존 미디어를 사용하지 않았다. 촬영 중 동작·이력 API 연결 검증 완료를 뜻하지 않는다.

실행 디렉터리: `C:\GitHub_Clone\AI_CCTV`.

```powershell
.\venv311\Scripts\python.exe -B -m unittest discover -s client_code/tests -p test_event_timeline.py -v
```

## 2단계 구현·검증

- `events/history.py`: EventHistory가 이력 전용 QNetworkAccessManager로 `GET /api/v1/events?limit=50`을 비동기 조회한다. 저장 EventStore/카메라 요청과 네트워크 객체를 공유하지 않는다. DB·백엔드·영상 처리·저장 큐는 수정하지 않았다.
- 로그인 후 관제 창 세션 연결 시 최근 50건을 조회한다. 모든 카메라·과거 서버 실행의 저장 이력이 대상이며 저장소 설정 조회/카메라 실행 성공을 기다리지 않는다.
- 타임라인 아래 `이전 이벤트 더 보기`로 마지막 발생 시각/이벤트 ID의 배타적 커서를 사용한다. 성공한 페이지를 event_id로 병합하고 시간/ID 역순 표시한다. 50건 미만이면 버튼을 숨기며 정확히 50건인 마지막 페이지는 다음 빈 페이지를 받은 뒤 숨긴다. 추가 조회 시 스크롤 위치를 보존한다.
- 로딩 중 중복 조회를 막는다. HTTP/시간 초과/잘못된 응답 시 기존 카드·커서를 유지하고 패널에 `다시 시도`를 표시한다. 초기 실패를 빈 이력 성공으로 표시하지 않는다. 재시도는 실패한 같은 페이지를 요청한다.
- 목록 구조·표시용 ID·종류·시간대·페이지 정렬/커서 진행을 검증한다. UI가 백엔드 모델이나 Repository를 import하지 않는다.
- 401은 기존 SessionManager의 갱신 결과를 기다리거나 이미 갱신된 토큰을 사용해 한 번 재요청한다. 반복 401은 세션 만료를 처리한다. 갱신 실패는 기존 세션 정책을 따르며 이력 패널은 오류를 안내한다.
- 로그아웃/세션 만료/관제 창 종료 준비 시 조회를 중단한다. 세대 번호로 취소 이전 응답을 무시하고, 갱신 완료 후에도 과거 요청을 재개하지 않는다. 이벤트 저장 큐의 종료 대기는 기존 순서를 유지한다.
- `test_event_history.py` 신규 8개, 기존 표시 3개·카메라 UI/API 6개, **총 17개 통과**(12.428초). 실제 Uvicorn/임시 SQLite/임시 저장소·계정과 Qt 네트워크로 55개 이력의 50+5 조회, 한국 날짜, 빈 이력, 오류·잘못된 응답 후 보존/재시도, 인증 갱신·반복 401, 시간 초과, 중복 요청 방지, Qt 타이머 지속, 로그아웃/만료 후 늦은 응답 무시, 실제 관제 창 세션 연결/종료를 확인했다.
- 임시 서버의 실제 조회 결과로 1280×720 관제 창과 오류/재시도 상태를 렌더링해 카드·버튼·메시지 배치를 확인했다. `temp/event_timeline_stage2/history_1280.png`, `error_1280.png`에 보존한다. 폰트는 검증 프로세스에만 등록했다.
- 운영 DB·계정·설정·기존 미디어는 사용/변경하지 않았다. 실제 카메라/촬영 중 동작은 실행하지 않았다. 2단계 당시 새 이벤트 자동 추가는 연결하지 않았으며 현재는 아래 3단계를 따른다.

## 3단계 구현·검증

- `EventCoordinator.event_saved`: 기존 응답 검증에 통과한 카메라 시작/중지 및 인물 등장/사라짐 POST 성공만 GUI 신호로 전달한다. 실패/미확인 응답, 저장소 설정 응답, 미디어 PATCH는 새 카드로 전달하지 않는다. 재요청으로 기존 행이 반환되어도 event_id로 중복을 제거한다.
- `gui.py`: 현재 관제 창의 EventHistory에 저장 성공 신호를 연결한다. ReID/영상/저장 큐/백엔드 API/DB 구조와 발생 기준은 유지한다.
- `EventHistory.receive_saved`: 현재 로그인에서 확인된 이벤트를 기존 이력에 병합한다. 초기/과거 페이지 응답은 목록 전체를 교체하지 않고 병합한다. 저장 결과는 조회 커서를 변경하지 않으며 이전 이력 범위를 건너뛰지 않는다. ID가 더 커도 발생 시각이 과거인 늦은 등장 등은 발생 시각 위치에 삽입한다.
- 타임라인은 기존 카드를 재사용한다. 맨 위를 보고 있으면 맨 위를 유지하고, 아래를 읽고 있으면 첫 보이는 카드의 ID와 화면 내 위치를 기준으로 스크롤을 복원한다. 같은 Qt 처리 주기의 연속 갱신도 마지막 렌더에서 한 번 복원한다. 미디어 PATCH는 카드 내용을 변경하지 않는다.
- 정상 종료 준비에서는 이력 HTTP만 중단하고 영상/이벤트 큐 정리 중 마지막 저장 성공은 계속 받는다. 로그아웃/세션 만료/새 세션으로 교체 후에는 이전 저장 결과를 무시한다. 기존 영상 정리 → 이벤트 큐 마무리 → 인증 폐기 순서를 변경하지 않았다.
- `test_event_live.py` 신규 **6개**, 이력 8개·표시 3개·기존 카메라 이벤트 14개·인물 이벤트 19개·카메라 UI/API 6개, **총 56개 통과**(28.251초). 실제 Uvicorn/임시 SQLite/Qt HTTP·저장 작업 스레드로 검증했다. 이후 테스트의 초기 조회를 저장 전 스냅샷으로 강화해 해당 1개도 통과했다. 화면 검토 중 불필요한 content.adjustSize로 카드 높이가 늘어나는 것을 제거한 뒤 관련 스크롤/표시 4개를 재실행해 통과했다.
- 신규 검증: 네 종류 저장 결과의 API/카드 식별값·발생 시각 일치, 실제 파일 경로 PATCH 후 카드 미추가, 저장 실패/잘못된 표시 입력 제외, 재전달 중복 방지, 초기 조회의 오래된 스냅샷과 새 저장 병합, 과거 조회 중 늦은 이벤트·조회 커서 유지, 날짜 경계를 포함한 스크롤 앵커·연속 갱신·맨 위 유지, 정상 종료 중 최종 중지 저장 반영, 로그아웃 후 과거 결과 차단, 실제 관제 창의 자동 연결과 종료 큐 완료를 확인했다.
- 실제 관제 창의 임시 이벤트 POST→DB→저장 응답→타임라인 경로를 다시 실행하고 `temp/event_timeline_stage3/live_1280.png`로 1280×720 배치를 확인했다. 네 종류 이벤트는 합성 관측으로 제출했으며 실제 카메라를 켜지 않았다. Windows 폰트 등록은 렌더 검증 프로세스에만 적용했다.
- 운영 DB·계정·설정·기존 미디어는 사용/변경하지 않았다. 커밋·푸시·브랜치 변경도 하지 않았다.

### 남은 검증·동작 범위

- 자동 반영은 **현재 관제 프로그램의 저장 성공 응답**을 기준으로 한다. 다른 프로그램/API에서 별도로 추가한 이력을 실시간 감시하는 기능은 없다. 다음 로그인/창 생성의 이력 조회에는 DB에 있는 이력이 포함된다.
- 저장 실패·응답 유실로 성공 확인이 끝내 되지 않은 이벤트는 즉시 카드로 추측 표시하지 않는다. 실제 DB 커밋 여부는 이후 이력 조회로 확인할 수 있다. 기존 제한 재시도·영속 복구 없음 정책을 유지한다.
- 실제 웹캠/RTSP 촬영 중 타임라인과 장시간 부하·많은 누적 카드의 성능은 미검증이다. 이번 결과를 물리 카메라 통합 검증으로 확대 해석하지 않는다. 썸네일/재생/필터/푸시도 추가하지 않았다.
